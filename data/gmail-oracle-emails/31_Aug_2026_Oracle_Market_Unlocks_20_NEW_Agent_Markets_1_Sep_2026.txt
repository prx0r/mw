**Research date:** 1 September 2026

This pass treats novelty as a hard constraint. I cross-checked the previous Oracle reports in Gmail and excluded the large set already covered, including the latest Samsara / Microsoft Security Store / Siemens / AppFolio / Geotab / Motive / Boomi / athenahealth / Coupa / CrowdStrike / Rippling / Jamf / Cisco / RealPage / Terraform / XSOAR / Celigo / Buildium / Canvas / Brightspace batch, plus all earlier creator, SaaS, commerce and developer marketplaces.

## 1. DigitalOcean Marketplace — cloud add-ons with native billing

**What an agent can sell.** SaaS Add-Ons and 1-Click infrastructure products: managed agent gateways, backup/restore utilities, monitoring adapters, narrow databases/search services, MCP gateways, webhook relays, security/configuration QA, cost analyzers, and vertical developer infrastructure.

**Autonomous workflow.** Oracle mines DigitalOcean community issues, Marketplace gaps and cloud changelogs → specialist worker builds a small hosted service/container/Helm artifact → Harbor CloudWorld provisions disposable Droplets/Kubernetes/database fixtures → tests installation, upgrades, rollback, secrets, rate limits, resource usage and failure recovery → worker generates vendor/listing/security/runbook material → human vendor approval → Marketplace launch → DigitalOcean handles billing/tax path → worker ingests install, support and service telemetry → patches versions automatically.

**Human dependency.** H1: vendor/business/payment approval remains human. Production and maintenance can become close to H0 once credentials and listing are live.

**Infrastructure / frontier.** DigitalOcean explicitly supports SaaS Add-Ons and 1-Click products. Its vendor page says SaaS Add-On vendors take home around **75% of revenue**. DigitalOcean’s 2026 financials also show a rapidly expanding AI/agentic customer base: Q2 guidance was raised after AI customer ARR grew sharply, so this is an increasingly relevant buyer surface rather than a stagnant cloud catalog.

**Demand / community.** Strong platform-level demand, but the right wedge is not another generic database image. Cloud communities repeatedly complain about painful migrations, monitoring/configuration drift and running production services safely. I found less clean 2026 Reddit evidence tied specifically to the Marketplace seller side than for Plesk/HRIS venues, so treat the public financial/vendor data as stronger than community anecdotes here.

**Why agents fit.** Infra products are extraordinarily testable. A worker can provision, mutate and destroy its own worlds and measure latency, uptime, installation success and cost.

**Moltwork assets.** `DigitalOceanPack`, `CloudWorld`, install/upgrade evaluator, cost/perf evaluator, MarketplaceSubmissionProcess, cloud-add-on specialist Worker.

**Economics.** Attractive if one product is self-serve and recurring. Unattractive if every customer needs manual DevOps consulting.

Official: https://marketplace.digitalocean.com/vendors

## 2. AppDirect Marketplace / AppDistribution — “integrate once, distribute to many marketplaces”

**What agents can sell.** SaaS, downloadable/web products and recurring digital services distributed through AppDirect-powered marketplaces and reseller channels. Particularly compelling for tiny agent utilities, compliance micro-SaaS, vertical workflow products and APIs that can be provisioned automatically.

**Autonomous workflow.** Oracle identifies a recurring B2B need → worker builds one self-service SaaS → integrates AppDirect provisioning/SSO/subscription callbacks → Harbor CommerceWorld simulates purchase, seat assignment, upgrade, cancellation and entitlement failure → product/profile/pricing generated → partner approval → publish once into AppDistribution → choose reseller/channel distribution → AppDirect handles transactions/reconciliation → usage/revenue data returns → worker improves the product and listing.

**Human dependency.** H1–H2: vendor/channel acceptance and legal/commercial setup are real gates, but subscription lifecycle and provisioning are API-driven after setup.

**Infrastructure / frontier.** AppDirect’s current docs expose REST, GraphQL, billing/subscription APIs and non-interactive API clients. AppDistribution explicitly says **integrate once, scale to many**, lets vendors choose where to distribute by clicking Publish, and handles transactions/payout reconciliation. Its catalog documentation says 600+ providers; the customer marketplace currently claims **16M subscribers** and thousands of products/services.

**Community intelligence.** General marketplace operators continue to identify liquidity and onboarding—not software implementation—as the hardest marketplace problem. That is exactly why AppDirect is interesting: it externalizes much of the channel/billing/provisioning machinery. The residual risk is channel approval and actual sell-through.

**Why agents fit.** A single specialist Worker can maintain one product while a `CrossVenueDistributionProcess` handles many AppDirect-powered sales channels.

**Moltwork assets.** `AppDirectPack`, entitlement/subscription World, provisioning evaluator, reseller-channel selector, `CrossVenueDistributionProcess`.

**Economics.** Very attractive if a proven product gains several channels with little incremental engineering. Poor if channel negotiation remains manual and no reseller has incentive to promote the product.

Official: https://www.appdirect.com/platform/appdistribution
API: https://developer.appdirect.com/

## 3. Vendasta Marketplace — white-label micro-SaaS sold through agencies

**What agents can sell.** White-label local-business utilities: reputation monitoring, lead qualification, appointment workflows, local SEO/reporting, vertical content/analytics, review-request workflows, lightweight CRM services and integrations agencies can resell under their own brand.

**Autonomous workflow.** Mine agency/reseller pain → build vendor product → implement Marketplace provisioning webhook and account/market branding → seed agency/client fixtures → Harbor AgencyWorld tests provisioning, cancellation, white-label rendering, partner segmentation and API failures → generate product page/SKU/price/support assets → vendor approval → resellers discover and activate → reseller/client usage and churn tracked → worker patches and generates variants for high-performing verticals.

**Human dependency.** H1–H2 for vendor onboarding/commercial approval; day-to-day product delivery can be H0/H1.

**Infrastructure.** Vendasta exposes Marketplace APIs, product APIs, signed JWT webhooks, Vendor Center testing and account/market branding. Its developer material describes a partner ecosystem of **66,000+ partners**; Marketplace material describes **250+ curated products**. White-labeling is explicitly encouraged because resellers are more likely to sell products they can brand as their own.

**Demand / practical constraints.** This is an underappreciated distribution model: the buyer is often an agency reselling to many SMBs. Community signal is thinner on Reddit than on vendor docs, but that itself reduces the “indie hacker crowd” competition signal. Main risk is reseller attention—good software can still sit unused if agencies do not understand how to sell it.

**Why agents fit.** Much local-business software is templated, API-driven and multi-tenant. Agents can manufacture vertical variants and maintain integrations cheaply.

**Moltwork assets.** `VendastaPack`, white-label evaluator, AgencyWorld, reseller onboarding Skill, verticalization Process.

**Economics.** Strong when one reseller activation fans out to many client accounts. Weak when support burden scales linearly with agencies.

Official: https://developers.vendasta.com/

## 4. Visma App Store — LLM-readable European accounting/business ecosystem

**What agents can sell.** Accounting, payroll/admin, invoice, reporting, reconciliation and vertical workflow integrations across Visma products; small cross-product connectors are the clearest wedge.

**Autonomous workflow.** Oracle mines country/product-specific gaps → Worker reads Visma’s LLM-oriented docs/index → registers app in Developer Portal → composes APIs/Flows/webhooks → Harbor AccountingWorld seeds companies, invoices, contacts and permissions → evaluator checks totals, permissions, sync/idempotency and local formatting → app submitted per target country with localized listing/pricing → human review → customers purchase/grant org access → usage/errors/revenue tracked → agent ports successful product into adjacent Visma markets.

**Human dependency.** H1–H2: app review and market-specific commercial/legal localization; implementation itself is highly structured.

**Frontier infrastructure.** Visma Connect publishes an **`llms.txt` documentation index** and “Copy page as Markdown for LLMs.” Developer Portal was updated June 5, 2026 and is API-driven; App Store lets third-party developers publish apps and customers grant organization data access. Visma also has Flows and webhook infrastructure.

**Demand/community.** Accounting/payroll integration demand is recurrent and country-specific, which creates many small niches. 2026 Reddit evidence is sparse relative to the platform’s European footprint; use Visma’s active App Store and product-specific community/support channels as primary demand signal rather than inventing sentiment.

**Why agents fit.** Schemas, ledgers and sync invariants are deterministic; localization can be encoded as market Schools.

**Moltwork assets.** `VismaPack`, AccountingWorld, localization School, permission evaluator, `VismaCountryPortingProcess`.

**Economics.** Excellent if one core integration ports across several countries/products. Poor if each jurisdiction requires substantial human accounting/legal interpretation.

Official: https://docs.connect.visma.com/docs/visma-app-store

## 5. Travelport Marketplace — travel-agency workflow products during an OAuth migration

**What agents can sell.** Travel-agent productivity tools, itinerary QA, fare/rule comparison helpers, booking evidence, NDC compatibility tools, agency reporting, queue/workflow extensions and Smartpoint/desktop products.

**Autonomous workflow.** Mine agency/Travelport developer pain → Worker selects a bounded agency workflow → build with Universal API / Smartpoint SDK / desktop SDK → synthetic itinerary/PNR/fare fixtures → Harbor TravelWorld checks booking state, cancellations, duplicate writes, fare/currency/date semantics and API errors → certification package → partner approval → Marketplace listing/purchase → usage/support telemetry → persistent worker tracks airline/NDC/API changes.

**Human dependency.** H2: Travelport developer approval/certification and commercial travel rules remain significant.

**Frontier unlock.** Travelport’s developer docs say its Marketplace is an **e-commerce platform** where agencies can browse/order partner products. More importantly, previous Trip Services auth endpoints were deprecated on **January 30, 2026**, with OAuth 2.0 becoming the current authentication flow. That standardization lowers one integration dependency while creating migration demand among older apps.

**Demand/community.** Travel distribution is full of high-value repetitive exception work. Direct Reddit seller evidence is modest, but the Marketplace supports actual agency purchase and current developer migration creates obvious compatibility pressure.

**Why agents fit.** Itinerary/fare/booking systems are structured state machines with large regression surfaces; a specialist can continuously replay them.

**Moltwork assets.** TravelportPack, TravelWorld, PNR invariant evaluator, OAuth migration Skill, NDC compatibility School.

**Economics.** Strong if a product saves an agent minutes on every booking or prevents costly booking errors. Weak for workflows requiring live human negotiation/service calls.

Official: https://developer.travelport.com/
Marketplace: https://marketplace.travelport.com/

## 6. SuiteCRM Store — unusually complete micro-plugin economics

**What agents can sell.** Timesheets, reporting, data-cleanup, synchronization, admin automations, vertical CRM modules, document generation and missing connectors.

**Autonomous workflow.** Mine SuiteCRM forum/store requests → build extension → disposable SuiteCRM matrix → Harbor CRMWorld tests install/uninstall, upgrades, permissions, record sync and DB migrations → seller packages screenshots/docs/version compatibility → Store submission → built-in licensing/trials/renewals → sales/support telemetry → worker updates product across SuiteCRM versions.

**Human dependency.** H1: seller account/listing approval. Much of commerce is handled by the Store.

**Infrastructure/economics.** SuiteCRM Store explicitly offers sellers a **license server, webhooks, transactions, renewals, abandoned-cart recovery, 30-day trials** and flat/per-user, monthly/yearly/one-time pricing. Seller documentation says developers retain **70%** and are paid monthly.

**Community signal.** A SuiteCRM developer publicly solicited feedback/beta testers for a timesheet plugin, asking users which features/pain mattered. That is exactly the discovery pattern Oracle can automate: repeated small workflow pain rather than broad CRM replacement.

**Why agents fit.** CRM plugins are mostly code, schemas, forms and deterministic state transitions.

**Moltwork assets.** `SuiteCRMPack`, CRMWorld, installer/migration evaluator, Store licensing Skill, plugin-maintainer Worker.

**Economics.** Excellent testbed: low market size but low production cost and native recurring commerce. Bad if support fragmentation across old installs dominates revenue.

Store: https://store.suitecrm.com/

## 10. Keap Marketplace — migration-debt integrations before XML-RPC retirement

**What agents can sell.** CRM/ecommerce sync, lead routing, invoice/payment bridges, campaign utilities, data cleanup, reporting and migration adapters.

**Autonomous workflow.** Oracle mines Keap integration complaints and deprecated endpoint usage → Worker builds OAuth2 REST v2 connector → sandbox fixture → Harbor CRMCommerceWorld tests contacts, opportunities, orders, custom fields, rate limits and retries → listing/partner review → Marketplace distribution → own SaaS billing or commercial integration model → API/support telemetry → migration worker continuously removes old XML-RPC assumptions.

**Human dependency.** H1–H2 for company/Marketplace registration and review.

**Frontier unlock.** Keap’s developer portal provides sandbox access and OAuth2. Marketplace material advertises visibility to around **100,000 small-business users**. More importantly, official January 2026 community threads discuss **XML-RPC retirement planned for December 2026** while REST v2 still has gaps. Keap also changed per-instance API traffic rules effective **June 8, 2026**. This is textbook temporary migration debt.

**Community demand.** Developers are publicly tracking v2 known issues and missing parity. A specialist agent can own the ugly compatibility layer while human developers avoid it.

**Why agents fit.** API migration is repetitive diff→fixture→patch work.

**Moltwork assets.** KeapPack, XMLRPC→REST migration Skill, CRMCommerceWorld, rate-limit evaluator, compatibility watcher.

**Economics.** Strong during migration if many existing integrations need a safe bridge. Declines once the ecosystem completes migration—Oracle should model the opportunity as time-decaying.

Official: https://developer.keap.com/

**Moltwork assets.** BambooHRPack, HRWorld, sync-fidelity evaluator, partner-readiness evaluator, rate-limit Skill.

**Economics.** Potentially excellent ACV, but unattractive as an MVP because the 100-customer gate makes Marketplace admission a downstream goal.

# Frontier Unlocks

The highest-value changes are not “a new AI model exists.” They are changes to the **economic execution surface**:

1. **Travelport OAuth migration (January 30, 2026):** older Trip Services auth endpoints are deprecated in favor of OAuth 2.0. This both reduces future credential friction and creates immediate migration demand.
2. **Visma’s LLM-readable developer surface:** `llms.txt`, Markdown-for-LLMs, API-driven Developer Portal, App Store permissions and workflow tooling make a large regional business ecosystem easier for agents to learn without bespoke documentation ingestion.
3. **Keap migration debt:** XML-RPC retirement is approaching while REST v2 gaps remain; June 2026 API traffic rules also changed. A compatibility specialist can monetize the transition.
4. **BambooHR standards improvement (effective September 14, 2026):** rate limiting moves to the standard 429 + Retry-After pattern, directly reducing ambiguity for autonomous clients.
5. **CloudBlue Marketplace & Hub OpenAPI:** its OpenAPI 3 surface was updated June 10, 2026, making multi-reseller product distribution more machine-readable.
6. **AppDirect’s mature non-interactive APIs + AppDistribution:** “integrate once, distribute to many” is one of the strongest economic-callability primitives in this scan because provisioning, subscriptions, billing and payout reconciliation are all platformized.
7. **Epic’s agent-integration wave in August 2026:** not self-serve yet, but multiple agent products appearing in Connection Hub indicate a high-value market changing from conventional integration to agent-delivered service.
8. **DigitalOcean’s agentic-cloud growth + native SaaS Add-On billing:** Marketplace vendors can sell recurring services into a cloud whose 2026 AI/customer metrics are growing quickly.

Oracle should explicitly track an `HLevelDelta` event:

`manual/proprietary auth → OAuth`
`human docs search → llms.txt / MCP / OpenAPI`
`listing only → native billing`
`single venue → multi-channel distribution`
`manual retry/ambiguous failures → standardized machine-readable errors`

These events can turn previously unattractive markets into viable autonomous businesses even when the underlying work has not changed.

# Human Dependency Reduction

## 1. Partner/certification dossier automation

Across Personio, Exact, Travelport, Sabre, Greenhouse, Lever, BambooHR, Creatio and Epic, the dominant remaining H2/H3 friction is not coding. It is the evidence package:

`artifact → permission inventory → data-flow diagram → threat/privacy model → sandbox evidence → screenshots/demo → reviewer credentials → version matrix → support SLA → listing copy → human sign-off → submit`

Build this once as `MarketplaceCertificationProcess` with venue adapters.

## 2. Declarative SaaS test-tenant factory

The highest-leverage Harbor investment is a factory that can seed/reset:

- CRMWorld: SuiteCRM / Sugar / Keap / Creatio
- HRWorld: Personio / BambooHR
- ATSWorld: Greenhouse / Lever
- AccountingWorld: Visma / Exact
- TravelWorld: Travelport / Sabre
- DistributionWorld: AppDirect / CloudBlue / Vendasta

The first venue pays for the World; every adjacent venue becomes cheaper.

## 3. OAuth and credential handoff

Do not bypass mandatory consent. Reduce it to one legitimate H1 action:

`Worker requests least-privilege scopes → HumanQueue consent → callback → credential self-test → worker resumes → token rotation/revocation automatically monitored.`

Travelport’s 2026 OAuth migration and several HR/CRM partner APIs make this especially valuable.

## 4. Compatibility-maintenance Worker

This scan reinforces that the agent advantage is often not creation but **owning a boring integration forever**:

`watch upstream changelog → detect schema/auth/version change → reproduce in World → patch → regression → release → attach evidence to WorkerVersion.`

Keap, Personio, Plesk, Exact and Travelport all have fresh evidence of exactly this kind of migration/breakage.

## 5. Cross-venue distribution Process

AppDirect/CloudBlue/Vendasta reveal a higher-order asset: once Moltwork has a proven SaaS product, the next worker should not build another product—it should distribute the same product through additional reseller ecosystems.

Add a metric:

**Distribution Leverage (DL) = expected reachable buyer channels after one integration / incremental engineering + human onboarding cost.**

That metric may rank AppDirect above many larger conventional app stores.

# Recommended experiments

**1. DigitalOcean SaaS Add-On.** Best clean autonomous economics in this batch: native recurring billing, roughly 75% vendor take-home, disposable test worlds and a rapidly growing AI/agent customer surface. Build one tiny agent infrastructure utility that is objectively measurable.

**2. SuiteCRM paid plugin.** Best cheap proof that Moltwork can go from complaint → plugin → Harbor → native license/trial/renewal → money. Much smaller TAM, but faster feedback and low human dependence.

**3. Keap migration worker.** Treat XML-RPC→REST v2 as a time-bounded arbitrage. Build a compatibility/reconciliation utility and measure whether a specialist Worker can outperform generic integration coding because it accumulates edge cases.

**4. AppDirect distribution test.** Only after one product is validated elsewhere: see whether a single AppDistribution integration materially lowers CAC by opening several reseller channels.

**5. Paired Greenhouse→Lever product.** Deliberately build the same narrow ATS utility twice. The experiment is not just revenue: measure how much `ATSWorld + School + Process + Worker` reuse reduces cost and improves quality on venue #2.

# Bottom line

The strongest new insight from this pass is that **reseller/distribution marketplaces may be more strategically important than another creator store**. AppDirect, CloudBlue and Vendasta let a successful agent-produced product propagate through *channels*, while DigitalOcean/SuiteCRM/Plesk provide cleaner direct-product experiments.

Moltwork should therefore distinguish three venue archetypes:

1. **Direct Store** — publish one artifact, buyers purchase it (SuiteCRM, Plesk, Creatio).
2. **Embedded SaaS Marketplace** — app/service integrates into host platform and is distributed to its customers (DigitalOcean, Personio, Keap, Exact).
3. **Distribution Network** — one integration can unlock many reseller marketplaces (AppDirect, CloudBlue, Vendasta).

The third category has the highest compounding potential because a proven Worker does not merely learn to make better products; it learns to **route the same product into more economic surfaces at falling marginal cost**.

<p>The highest-value changes are not “a new AI model exists.” They are changes to the <strong>economic execution surface</strong>:</p>

<li><strong>Travelport OAuth migration (January 30, 2026):</strong> older Trip Services auth endpoints are deprecated in favor of OAuth 2.0. This both reduces future credential friction and creates immediate migration demand.</li>
<li><strong>Visma’s LLM-readable developer surface:</strong> <code>llms.txt</code>, Markdown-for-LLMs, API-driven Developer Portal, App Store permissions and workflow tooling make a large regional business ecosystem easier for agents to learn without bespoke documentation ingestion.</li>

<li><strong>CloudBlue Marketplace &amp; Hub OpenAPI:</strong> its OpenAPI 3 surface was updated June 10, 2026, making multi-reseller product distribution more machine-readable.</li>
<li><strong>AppDirect’s mature non-interactive APIs + AppDistribution:</strong> “integrate once, distribute to many” is one of the strongest economic-callability primitives in this scan because provisioning, subscriptions, billing and payout reconciliation are all platformized.</li>

<li><strong>DigitalOcean’s agentic-cloud growth + native SaaS Add-On billing:</strong> Marketplace vendors can sell recurring services into a cloud whose 2026 AI/customer metrics are growing quickly.</li>
</ol>

<p><code>manual/proprietary auth → OAuth</code><br>

Human Dependency Reduction

1. Partner/certification dossier automation
<p>Across Personio, Exact, Travelport, Sabre, Greenhouse, Lever, BambooHR, Creatio and Epic, the dominant remaining H2/H3 friction is not coding. It is the evidence package:</p>
<p><code>artifact → permission inventory → data-flow diagram → threat/privacy model → sandbox evidence → screenshots/demo → reviewer credentials → version matrix → support SLA → listing copy → human sign-off → submit</code></p>
<p>Build this once as <code>MarketplaceCertificationProcess</code> with venue adapters.</p>

2. Declarative SaaS test-tenant factory
<p>The highest-leverage Harbor investment is a factory that can seed/reset:</p>
<ul>
<li>CRMWorld: SuiteCRM / Sugar / Keap / Creatio</li>
<li>HRWorld: Personio / BambooHR</li>
<li>ATSWorld: Greenhouse / Lever</li>
<li>AccountingWorld: Visma / Exact</li>
<li>TravelWorld: Travelport / Sabre</li>
<li>DistributionWorld: AppDirect / CloudBlue / Vendasta</li>
</ul>
<p>The first venue pays for the World; every adjacent venue becomes cheaper.</p>

3. OAuth and credential handoff
<p>Do not bypass mandatory consent. Reduce it to one legitimate H1 action:</p>
<p><code>Worker requests least-privilege scopes → HumanQueue consent → callback → credential self-test → worker resumes → token rotation/revocation automatically monitored.</code></p>
<p>Travelport’s 2026 OAuth migration and several HR/CRM partner APIs make this especially valuable.</p>

4. Compatibility-maintenance Worker
<p>This scan reinforces that the agent advantage is often not creation but <strong>owning a boring integration forever</strong>:</p>
<p><code>watch upstream changelog → detect schema/auth/version change → reproduce in World → patch → regression → release → attach evidence to WorkerVersion.</code></p>
<p>Keap, Personio, Plesk, Exact and Travelport all have fresh evidence of exactly this kind of migration/breakage.</p>

5. Cross-venue distribution Process
<p>AppDirect/CloudBlue/Vendasta reveal a higher-order asset: once Moltwork has a proven SaaS product, the next worker should not build another product—it should distribute the same product through additional reseller ecosystems.</p>
<p>Add a metric:</p>
<p><strong>Distribution Leverage (DL) = expected reachable buyer channels after one integration / incremental engineering + human onboarding cost.</strong></p>
<p>That metric may rank AppDirect above many larger conventional app stores.</p>

Recommended experiments
<p><strong>1. DigitalOcean SaaS Add-On.</strong> Best clean autonomous economics in this batch: native recurring billing, roughly 75% vendor take-home, disposable test worlds and a rapidly growing AI/agent customer surface. Build one tiny agent infrastructure utility that is objectively measurable.</p>
<p><strong>2. SuiteCRM paid plugin.</strong> Best cheap proof that Moltwork can go from complaint → plugin → Harbor → native license/trial/renewal → money. Much smaller TAM, but faster feedback and low human dependence.</p>
<p><strong>3. Keap migration worker.</strong> Treat XML-RPC→REST v2 as a time-bounded arbitrage. Build a compatibility/reconciliation utility and measure whether a specialist Worker can outperform generic integration coding because it accumulates edge cases.</p>
<p><strong>4. AppDirect distribution test.</strong> Only after one product is validated elsewhere: see whether a single AppDistribution integration materially lowers CAC by opening several reseller channels.</p>
<p><strong>5. Paired Greenhouse→Lever product.</strong> Deliberately build the same narrow ATS utility twice. The experiment is not just revenue: measure how much <code>ATSWorld + School + Process + Worker</code> reuse reduces cost and improves quality on venue #2.</p>

Bottom line
<p>The strongest new insight from this pass is that <strong>reseller/distribution marketplaces may be more strategically important than another creator store</strong>. AppDirect, CloudBlue and Vendasta let a successful agent-produced product propagate through <em>channels</em>, while DigitalOcean/SuiteCRM/Plesk provide cleaner direct-product experiments.</p>
<p>Moltwork should therefore distinguish three venue archetypes:</p>
<ol>
<li><strong>Direct Store</strong> — publish one artifact, buyers purchase it (SuiteCRM, Plesk, Creatio).</li>
<li><strong>Embedded SaaS Marketplace</strong> — app/service integrates into host platform and is distributed to its customers (DigitalOcean, Personio, Keap, Exact).</li>
<li><strong>Distribution Network</strong> — one integration can unlock many reseller marketplaces (AppDirect, CloudBlue, Vendasta).</li>
</ol>
<p>The third category has the highest compounding potential because a proven Worker does not merely learn to make better products; it learns to <strong>route the same product into more economic surfaces at falling marginal cost</strong>.</p>
