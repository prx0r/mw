## 1. Google Cloud Marketplace — A2A AI Agents as a Service

**Why this is here despite prior Google Cloud coverage.** This is a material new unlock, not a repeat. Google’s seller documentation updated **26 August 2026** now explicitly supports **AI Agents as a Service using the Agent2Agent (A2A) protocol**, alongside SaaS and Kubernetes packaging. Sellers provide an A2A Agent Card, integrate Marketplace procurement and metering, pass review, and can surface the agent to Gemini Enterprise users.

**What agents can sell.** Bounded specialist agents: cloud-cost investigator, log-evidence agent, document-compliance checker, data-quality agent, support triage agent, vertical research agent, migration planner, security evidence collector, or other narrow A2A capabilities with measurable outputs.

**Autonomous workflow.** Oracle mines buyer pain/changelogs → specialist Worker builds an A2A service → generates Agent Card → Harbor CloudAgentWorld provisions deterministic fixtures → evaluator checks capability discovery, schema fidelity, latency, cost, failure handling and unsafe action boundaries → Marketplace package + pricing generated → human publisher/security approval → listing → Google handles procurement/entitlements → Service Control/Marketplace metering tracks usage → revenue/usage/errors flow back to Hydra → Worker maintains product.

**Human dependency.** H1–H2: publisher/legal/security approval and accountable claims remain human. Normal execution, metering and maintenance can approach H0.

**Infrastructure.** A2A protocol; Gemini Enterprise Agent Marketplace; Google Cloud Marketplace Producer Portal; Partner Procurement API; Service Control API; Pub/Sub; Agent Registry; gcloud/Terraform registration.

**Demand / constraints.** This is strategically important because Google has turned “agent” into a transactable Marketplace object rather than merely a workload running on cloud. Competition will accelerate rapidly, so the winning wedge is a measurable specialist capability, not generic chat.

**Moltwork assets.** `GoogleA2APack`, `AgentCommerceWorld`, Agent Card compiler/evaluator, metering evaluator, security-boundary School, MarketplaceCertificationProcess, specialist commercial Worker.

**Attractive if:** usage has a natural meter and value per call exceeds inference/ops/support cost. **Unattractive if:** procurement/security review is longer than product lifetime or the agent is an undifferentiated LLM wrapper.

Official: https://cloud.google.com/marketplace/docs/partners/ai-agents

## 2. Setapp Marketplace — Single-App Distribution

**New unlock.** In 2026 Setapp added direct **single-app purchases and subscriptions**, separate from its classic membership bundle. Current docs say developers receive **85% of subscription revenue** and **75% of one-time purchase revenue**; Setapp handles activation, licensing, billing, tax and first-line support. This is a major reduction in the non-code work required to monetize a small Mac/web utility.

**What agents can sell.** Narrow Mac utilities: batch file/content operations, local data QA, developer helpers, media metadata tools, privacy-safe workflow utilities, menu-bar automation and specialist productivity software.

**Workflow.** Oracle mines Mac workflow complaints → Worker creates app → macOS fixture/VM tests → Harbor checks install/update/uninstall, permissions, file-system safety, CPU/memory and UX invariants → generate app metadata/docs → human Setapp review/signing → Marketplace → transaction/licensing handled by Setapp → usage/revenue feedback → compatibility Worker follows macOS updates.

**H-level.** H1. Code lifecycle can become close to H0; curation/signing/publisher identity remain human.

**Demand/community.** Setapp says the catalog has 250+ apps in 2026. Community reaction to standalone sales is mixed: users explicitly complain about “AI-built slop” and abandoned apps, which makes **quality + perpetual maintenance** the agent opportunity rather than high-volume generation.

**Moltwork assets.** `SetappPack`, MacVM World, entitlement/licensing evaluator, notarization/release Process, persistent Mac-specialist Worker.

**Economics.** Strong for self-contained utilities with near-zero marginal support. Weak if the product needs constant handholding or duplicates an incumbent Setapp app.

Official: https://docs.setapp.com/docs/setapp-marketplace-overview

## 3. Thinkific App Store

Thinkific reports **50,000+ course creators, $650M+ earned by creators, 100M+ courses taken and 165+ countries**. Its third-party apps use OAuth, Admin APIs and programmable webhooks, and public apps undergo quality/security review.

**What agents sell.** Course QA, completion/evidence reporting, cohort analytics, certificate workflows, content migration, CRM/community sync, learner-support triage, accessibility checks and vertical education operations.

**Workflow.** Oracle mines creator/support pain → Worker implements OAuth app → synthetic Thinkific school with courses/users/orders → Harbor `CourseCommerceWorld` tests enrollment, refunds, deleted users, webhook retries, permissions and partial failure → listing/security docs generated → human review → app installed through Store → external SaaS/native app billing → events and retention tracked → Worker patches.

**H-level.** H1–H2 due app review/privacy and educational-data responsibility.

**Frontier infrastructure.** OAuth2, Admin API, Webhooks API; a **User Deleted webhook was added Feb 4, 2026**, improving lifecycle integrity.

**Community signal.** Creator businesses repeatedly need Zapier-style glue and reporting; Thinkific itself positions Zapier as a way to automate tasks that are not covered by App Store apps, which is effectively a map of missing product opportunities.

**Moltwork assets.** ThinkificPack, CourseWorld, webhook/idempotence evaluator, creator-ops School, OAuth installation Skill.

**Economics.** Attractive when one app saves every creator recurring admin time. Unattractive if the feature is only relevant to a tiny plan tier or requires manual instructional-design work.

Official: https://developers.thinkific.com/

## 4. Webasyst Store

This is one of the most overlooked software marketplaces in the scan. Webasyst explicitly invites developers to build apps/plugins, provides front/back/access-rights/REST infrastructure, handles cloud hosting and Installer-based updates, supports basic/premium/freemium editions, and says developers receive **80% of app sales** with monthly payouts.

**What agents sell.** Shop-Script catalog tools, CRM utilities, reporting, bulk edits, data-quality products, payment/shipping adapters, order workflows and niche ecommerce administration.

**Workflow.** Mine Store/support gaps → generate PHP app/plugin → disposable Webasyst/Shop-Script fixture → install/upgrade/rollback/data-migration evaluation → screenshot/description packaging → Store submission → Installer handles delivery/updates → sales/ratings/support tracked → Worker maintains versions.

**H-level.** H1.

**Demand evidence.** Current Store products show real recurring economics: one Shop-Script plugin lists **800+ installs**, 43 ratings and pricing around $15.99 monthly / $49 yearly / $139 lifetime. The developer leaderboard shows long-lived vendors with dozens to hundreds of plugins.

**Community constraint.** English-language Reddit signal is thin; this is partly a geography/language issue. Treat Store installs, ratings and developer longevity as stronger evidence than pretending Reddit is representative.

**Moltwork assets.** WebasystPack, EcommerceAdminWorld, install/migration evaluator, Shop-Script School, multilingual listing Process.

**Economics.** Very interesting because low competition + native update delivery can offset smaller total market size.

Official: https://developers.webasyst.com/build-apps/

## 5. BricsCAD Application Catalog / Online Store

Bricsys says **1,500+ external developers** create BricsCAD apps and **400+ publish directly to the Application Catalog**. Its developer surface emphasizes straightforward AutoCAD app porting through BRX/.NET/LISP and an Application Catalog/Online Store.

**What agents sell.** CAD standards checks, layer/entity cleanup, batch drawing operations, BOM extractors, drawing QA, GIS/engineering adapters, quantity tools and AutoCAD→BricsCAD ports.

**Workflow.** Oracle mines CAD forum requests → code or port application → Harbor CADWorld loads synthetic DWGs → evaluator checks geometry invariants, commands, undo behavior, performance and BricsCAD-version matrix → generate installer/docs → human developer/catalog approval → publisher commerce/listing → issues/versions monitored → compatibility Worker patches.

**H-level.** H1–H2; publisher relationship and domain-engineering assertions remain human.

**Demand.** CAD labor is expensive, so a utility saving minutes per drawing can support far higher prices than generic consumer software. The existing 400+ publisher count proves an established extension economy while remaining much smaller than AutoCAD’s ecosystem.

**Agent suitability.** Excellent: CAD state can be generated, mutated and tested deterministically; agents are also unusually good at repetitive API-porting work.

**Moltwork assets.** BricsCADPack, DWG World, geometry evaluator, AutoCADPortingProcess, CAD API School.

Official: https://developer.bricsys.com/

## 6. Huawei AppGallery / HarmonyOS

**What agents sell.** Huawei/HarmonyOS-specific utilities, developer integration tools, paid mobile utilities, subscription apps, HMS bridges and device-management/productivity apps.

**2026 frontier.** AppGallery Connect supports paid apps, subscriptions/IAP and sandbox testing; Huawei’s server API guidance updated **April 7, 2026** recommends **Service Accounts**, which are replacing older API-client credentials. This is the kind of machine-to-machine credential improvement Oracle should score as an H-level reduction.

**Workflow.** Mine HarmonyOS/Huawei developer/user gaps → Worker builds app/HMS integration → Huawei Cloud Phones + emulator fixtures → test IAP/ads/account lifecycle → human physical-device final check + publisher/payment setup → AppGallery submission → paid download/IAP → analytics/reviews → agent maintains OS/device compatibility.

**H-level.** H1–H2. Physical hardware and payout/regional constraints are real.

**Community signal.** A July 29, 2026 Godot developer reported there was no Huawei Ads/IAP plugin, built one, and validated it with **Huawei Cloud Phones**, but still needed a real device check. Another June 2026 indie described AppGallery as the most developer-friendly of several Chinese stores. Conversely, developers report cross-border payout friction. That is a textbook agent wedge plus a real commercial constraint.

**Moltwork assets.** HuaweiPack, CloudPhoneWorld, HMS/IAP evaluator, physical-device HumanQueue, Godot/HarmonyOS integration School.

Official: https://developer.huawei.com/consumer/en/
