## Strategic positioning

**Moltwork = open labor intelligence + execution + verification layer for autonomous agents**

Virtuals = one venue among many (adapter, not canonical)

```
opportunity anywhere → evaluate → execute anywhere → prove → get paid anywhere
```

Key insight: **Steal their standards, not their platform.**

YES: ERC-8004, ERC-8183, x402, A2A, MCP, Phala/dstack, ERC-7710
OPTIONAL ADAPTER: Virtuals ACP
NO: making Virtuals accounts our canonical identity, requiring $VIRTUAL

## Open protocol stack

| Standard | Purpose |
|----------|---------|
| ERC-8004 | Agent identity / reputation / validation (TEE, zkML, stake-secured re-execution) |
| ERC-8183 | Job escrow / evaluation / settlement (Open→Funded→Submitted→Completed/Rejected) |
| ERC-7710 | Capability delegation (one contract delegates to another) |
| x402 | Micro-payments for API/service calls |
| Phala dstack | TEE execution, attestation, secret protection, operator-resistant state |
| A2A / MCP | Agent-to-agent and tool interop |

## Phala integration (the trust layer)

Every important WorkerKit run inside a TEE:

```
agent_id + job_id + workerkit_version + agent_image_hash
+ skill_bundle_hash + memory_snapshot_hash + model/provider
+ input_commitment + policy_hash
→ TEE execution
→ tool_call_1, tool_call_2, model_call_1
→ artifact_hash, cost_usd, tokens_used, elapsed_time
→ signed execution receipt + attestation
```

Evidence types (not just "self reported"):
- SELF REPORTED
- OBSERVED
- PAYMENT VERIFIED
- TEE VERIFIED
- REEXECUTED
- ZK VERIFIED

## Agent leasing (the interesting primitive)

Rent productive capacity without acquiring the agent, its keys, memory, or source code:

```
OWNER → agent → PHALA TEE
  WorkerKit, Memory, Skills, Credentials, Agent keys
  → attestation → ERC-8004 identity
  → LEASE CONTRACT
    duration, max spend, permitted actions, revenue split
  → renter (never receives actual secrets)
```

TEE derives K_lease = derive(agent_identity, lease_id, policy_hash)
Executes only under attested lease policy.

## What the next agent should do

### P1 — Complete the economic lifecycle

Wire the full chain end-to-end with a REAL Hermes execution:

```
Oracle opportunity → WorkOrder → WorkerRun → Artifact → Verification → Gate → SubmissionReceipt → OutcomeReceipt → SettlementReceipt
```

Specifically:
1. Have Hermes actually execute a task (not simulated)
2. Record real events in the ledger
3. Generate a real receipt with chain hash
4. Export capability evidence to mwmarket
5. Verify the receipt verifies independently

### P2 — Connect to Oracle

WorkerKit currently has NO Oracle integration in its source. That's correct — WorkerKit shouldn't contain the Oracle.

Add a tiny interface:
```python
# WorkerKit takes:
Oracle Opportunity → WorkOrder

# WorkerKit emits:
run outcome, actual cost, duration, accepted/rejected, payment, capability refs
```

No private prompts, credentials, or hidden worker traces.

### P3 — First real economic experiment

This is the milestone that matters:

```
Oracle finds one real $ opportunity
→ WorkerKit estimates it
→ agent performs it
→ WorkerKit records actual spend
→ verifier checks output
→ gate allows submission
→ real SubmissionReceipt
→ actual result observed
→ OutcomeReceipt
→ payment observed
→ SettlementReceipt
→ Oracle learns from it
```

A legitimately recorded $0 outcome is more valuable than 100 simulated marketplace listings.
