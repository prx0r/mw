# Oracle Classification Feedback — 2026-09-01

## Rules Learned

### H0 — Fully autonomous (agent does everything)
- Metaculus forecasting questions
- GitHub bugs with [Bug] tag
- Simple code tasks: "build X", "implement Y", "fix Z"
- Scripts, automation, API integrations
- Data processing, JSON comparisons
- BountyBook $5+ code tasks (no harm entering, accumulate experience)

### H1 — One-time human setup, then autonomous
- Complex code bounties needing repo access or API keys
- Multi-file implementations
- Research requiring domain expertise

### H2 — Human approval required per task
- Design work (logos, UI, branding)
- Customer support

### H4 — Human-only (skip these)
- Superteam content/video/creator bounties (ALL of them)
- RentAHuman physical tasks (flyers, signs, DJ, car detail)
- RentAHuman HITL transcription
- Daydreams creative tasks (make a world, paintbot)
- Video creation, social media content, pure writing

## Key Insight
> "BountyBook is cool, there's no harm entering shit like that. The point is for each category we store the whole process and learn from it."

Classification is NOT about filtering out low-value tasks.
It's about knowing what an agent CAN do autonomously.
Every H0/H1 task is practice. Every run teaches something.

## User Decisions
- Superteam content = H4 always (confirmed)
- Low-value code ($5-12) = H0, keep them
- NEAR AI $0 tasks = H0, keep them (practice)
- Research JSON = H0 (agent can write structured comparisons)
- HITL Transcription = H4 (skip)

## Unresolved
- Daydreams: code tasks = H0, creative tasks = H4 (split by content)
- RentAHuman: physical = H4, API/code tasks = H0/H1
